# Jak rozwijać tę bazę wiedzy

Poprawki i nowe scenariusze zgłaszaj przez Issues lub pull request, z opisem problemu, proponowanym brzmieniem i źródłem. Nie publikuj danych klientów, sekretów ani kodu wykonanego dla klientów. Podatności bezpieczeństwa zgłaszaj prywatnie zgodnie z [SECURITY.md](SECURITY.md).

Zapraszamy do zgłaszania poprawek, pytań, dodatkowych scenariuszy UAT i wniosków z wdrożeń Odoo, pod warunkiem, że można je udostępnić publicznie.

## Dobra propozycja zmiany

- Opisuje realny problem wdrożeniowy i moment, w którym pojawia się w projekcie.
- Podaje rekomendowaną procedurę, warianty i kryterium decyzji.
- Przykład jest zmyślony, bez danych firmy i klientów.
- Rozróżnia zasady ogólne od ograniczeń konkretnej wersji Odoo.
- Linkuje do dokumentacji producenta, gdy dotyczy specyficznych zachowań systemu.

## Przed zgłoszeniem zmiany

1. Sprawdź, czy temat nie jest już opisany i czy nie jest specyficzny dla jednej wersji.
2. Usuń wszelkie dane osobowe, zrzuty ekranu z systemów klientów, nazwy hostów, ID użytkowników, tokeny, hasła i wrażliwą konfigurację.
3. Nie publikuj kodu objętego cudzym prawem autorskim ani kodu wykonywanego dla klientów.
4. W treści zgłoszenia podaj sekcję, problem i proponowane brzmienie.
5. Jeżeli zgłaszasz podatność bezpieczeństwa, nie opisuj jej publicznie; patrz [SECURITY.md](SECURITY.md).

## Styl materiałów

Używaj języka polskiego, krótkich sekcji, pytań możliwych do zadania klientowi, checklist z oczekiwanym dowodem oraz terminów Odoo tam, gdzie są potrzebne. Angielski termin podawaj w nawiasie przy pierwszym użyciu w rozdziale i dopisz go do [słownika](docs/16-slownik.md). Nie publikuj niesprawdzonych porad prawnych ani księgowych.

## Autorstwo, wersje i daty

- Przy zmianie merytorycznej podaj rzeczywistą datę, wersję Odoo, której dotyczy zmiana, i link do źródła.
- Nie wpisuj fikcyjnych recenzentów ani dat przeglądu. Materiał oznaczamy jako zweryfikowany tylko po faktycznym przeglądzie przez wskazaną osobę.
- Nie zmieniaj daty aktualizacji bez zmiany treści.
- Każdą zmianę opisz w [CHANGELOG.md](CHANGELOG.md).
